6. SECURITY & GEO-FENCE VERIFICATION ENGINE (§64)
================================================================================
Frontend geolocation is UX-only. THE BACKEND IS THE FINAL AUTHORITY. Implement a
GeofenceService with the exact Haversine formula:

```
function haversineDistance(lat1, lon1, lat2, lon2): number {
  const R = 6371000;
  const toRad = (d) => (d * Math.PI) / 180;
  const dLat = toRad(lat2 - lat1);
  const dLon = toRad(lon2 - lon1);
  const a = Math.sin(dLat/2) ** 2 +
            Math.cos(toRad(lat1)) * Math.cos(toRad(lat2)) * Math.sin(dLon/2) ** 2;
  return R * 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a)); // meters
}
```

CHECK-IN VALIDATION PIPELINE (5 steps, fail-fast, in this order):
1. USER ACTIVE        -> user exists, user.isActive true, employee exists,
                         employee.employmentStatus in (ACTIVE, ON_NOTICE).
2. DUPLICATE          -> no Attendance row for today (employeeId+date) with checkOut == null
                         (open active session) -> else CONFLICT ATTENDANCE_STATE_INVALID.
3. GEOFENCE           -> load OfficeLocation by officeId (assigned office).
                         distance = haversine(location, office).
                         if distance > office.radiusMeters -> 422 GEOFENCE_OUTSIDE_RADIUS
                         (retain the computed meters in `details` and store distanceMeters).
4. ACCURACY GUARDRAIL -> if location.accuracy > GPS_MAX_ACCURACY (>= 100m) -> 422
                         GEOFENCE_LOW_ACCURACY (weak/mocked GPS guard). The frontend may
                         pass accuracy 0 when unavailable -> reject with LOW_ACCURACY too.
5. SHIFT EVALUATION   -> compare check-in timestamp (Asia/Kolkata wall clock on the
                         attendance `date`) with shift.startTime:
                         - within startTime .. startTime+gracePeriodMinutes  -> PRESENT, isLate=false
                         - within startTime+grace .. startTime+lateThreshold  -> LATE  , isLate=true
                         - after lateThreshold                                -> LATE  (recorded; daily
                           late-status derived later; a shift-missed day is ABSENT via nightly job)
                         - before shift start (early check-in) -> INCOMPLETE unless within a
                           configurable early-window (default 15 min before startTime).

CHECK-OUT VALIDATION:
- Requires an open Attendance for today (checkOut == null).
- Optional geofence re-check: if checkOut location provided, validate same radius
  (soft warn vs hard reject — decide by config GEO_CHECKOUT_ENFORCE=true default).
- Compute workingHours = (checkOut - checkIn) - breakMinutes; if workingHours >
  8h mark OT-eligible (report layer).

BREAK VALIDATION:
- start-break requires open attendance + not already on break.
- end-break requires BreakLog with endTime == null; only ONE active break at a time.
- On check-out with an active break, close it first (endTime = checkOut).

NIGHTLY/ON-DEMAND ATTENDANCE STATUS ROLLUP (statusEngine service):
- Working-day calendar: exclude Sundays (week_off) and Holidays (holiday) for the
  employee's office/calendar.
- No open record on a working day -> ABSENT.
- checkIn exists but no checkOut -> INCOMPLETE.
- Check shifts, minimumWorkingHours (>= 4h -> full day, <4h -> HALF_DAY) etc.
- Approved leave on a date -> LEAVE. (leave approval writes/marks attendance row.)

AUDIT + SECURITY:
- argon2id password hashing; refresh tokens stored hashed (SHA-256), single-use rotation.
- Rate limit auth endpoints (5/min per IP), global throttler default.
- Never log or return password fields. Keep secrets only in env.
- Final validation ALWAYS server-side; never trust frontend `status` inputs.
